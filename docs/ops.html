How changes are made

Nothing changes until you say yes to that change.

01 · PLAN

What and why

  • Plain-English plan
  • Dependent rules, reports, objects
  • Sandbox or production named
02 · IMPACT

What it will do

  • Emails customers? Creates CTAs? Overwrites data?
  • The exact command, shown first
  • Sandbox recommended for production changes
03 · APPROVE

Your yes, then proof

  • A yes covers one change only
  • Result read back and compared
  • Logged in changelog.md
Nothing runs before this step

Sandbox named first

The plan names sandbox or production. A production change includes a recommendation to try it in sandbox.

Inactive until you ask

New rules stay inactive. Journey programs stay unpublished unless you ask otherwise.

For your security review

What you need, and what to check before rollout.

The Admin CLI is for tenant configuration: rules, reports, Journey programs, scorecards. MCP is how skills query accounts with each CSM's own permissions.

Starter kit

To run the audit

  • Gainsight Admin CLI, logged in
  • An AI agent that can run terminal commands
  • A working folder; add intent/ to its ignore list
Advanced kit

To build and change

  • Super admin CLI login
  • One OAuth app: Read and Write scopes, PKCE, local callback
  • Node.js and Python 3
  • A folder outside any git repository
CSM handoff

Before the team uses skills

  • Copilot prompts need no setup from you
  • Skills: OAuth with PKCE, one login per person, in the AI agent your team uses
  • Sign in as a non-admin and a region-restricted user, and compare the agent with the product
  • Confirm the provider's data handling, then send the team to the CSM cookbook

Before you ask

Questions CS Ops asks first

Where does tenant data go?

Audit files and the tenant brain stay in your local folder. Your AI agent processes what it reads under your provider's policy. Do not commit these files.

Is this a supported Gainsight product?

These are sample kits maintained in the open. For CLI or MCP help, use Gainsight Support.
