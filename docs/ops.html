How changes are made

Nothing changes until you say yes to that change.

01 · PLAN

What and why

  • Plain-English plan
  • Dependent rules, reports, objects
  • Sandbox or production named
02 · IMPACT

What it will do

  • Emails customers? Creates CTAs? Overwrites data?
  • The exact command, shown first
  • Sandbox recommended for production changes
03 · APPROVE

Your yes, then proof

  • A yes covers one change only
  • Result read back and compared
  • Logged in changelog.md
Nothing runs before this step

New rules are left inactive and Journey programs unpublished unless you ask otherwise.

Before you ask

Questions CS Ops asks first

Where does tenant data go?

Audit files and the tenant brain stay in your local folder. Your AI agent processes what it reads under your provider's policy. Do not commit these files.

Can it change production by accident?

The starter kit cannot write. The advanced kit stops before each write and waits for a yes on that specific change.

Admin CLI or MCP?

The Admin CLI is for tenant configuration: rules, reports, Journey programs, scorecards. MCP is how Claude skills query accounts with each CSM's own permissions. Copilot prompts don't need that connection.

Is this a supported Gainsight product?

No. These are sample kits maintained in the open. For CLI or MCP help, use Gainsight Support.
